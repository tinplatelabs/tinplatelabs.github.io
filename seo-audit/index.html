What it solves

An SEO audit means checking dozens of things on every page: title and description lengths, one H1, a self-referencing canonical, no stray noindex, valid hreflang, social cards, structured data, alt text, broken links, redirects. Desktop crawlers do it on one machine; hosted audit services charge per seat.

SEO Audit Tool fetches each page once and returns one record per page: the facts, an indexability verdict with the reason, a 0-100 score and the issues sorted most severe first, each with a fix. It can crawl a site (same site only, robots.txt obeyed) and writes a site summary with duplicate titles and descriptions, broken links and the issues that hit the most pages. Deterministic rules: no browser, no AI, same verdict every run.

  • Indexability: HTTP status, every redirect hop, robots meta and X-Robots-Tag (generic and Googlebot/Bingbot), canonical in HTML and the Link header.
  • Content: title and meta description presence, duplicates and length, heading outline and skipped levels, word count, charset, doctype, favicon, URL hygiene.
  • Structured data: JSON-LD parsed (including @graph) with @type values and JSON errors by line and column; microdata and RDFa types.
  • hreflang codes validated, duplicates, self-reference and x-default; Open Graph and Twitter card tags.
  • Images without alt or dimensions, internal/external/nofollow links, mixed content, viewport, response time, HTML size and compression.
  • Opt-in broken-link check (HEAD with GET fallback), each unique URL once per run, listed with the pages it is on.
  • Site summary in the key-value store: average score, top issues by pages affected, duplicate titles and descriptions, non-indexable pages, slowest pages, crawl coverage.

Limits

  • 10,000 start URLs per run and 10,000 pages per site; 5 MB of HTML per page.
  • Same-site crawl only (the start host and the host it redirects to); robots.txt is always obeyed.
  • JavaScript is not executed: pages are audited as served, which is what search engines see before rendering.
  • Only public internet addresses are reachable.

FAQ

How is the score calculated?

Each page starts at 100 and loses 30, 12, 6 or 2 points per critical, high, medium or low issue (floor 0). Category scores use the same rule per category. Issues are sorted most severe first, so the first one is the one to fix first.

Does it check Core Web Vitals?

No. It runs no browser, so it reports server response time, HTML size and compression instead. Use a Lighthouse-based tool for lab Core Web Vitals.

Can it audit a page my robots.txt blocks?

No, robots.txt is always obeyed. To audit your own blocked pages, add User-agent: TinplateSEOAudit with Allow: / to robots.txt.

Where are the duplicate titles?

In the site summary (SITE_SUMMARY in the run's key-value store, linked from the Output tab), grouped with the pages that share them. Only indexable pages count.

Why are 404 pages charged?

An error page is a finding you act on, so it gets a full record. Pages that never answer, pages blocked by robots.txt and non-HTML files are free.
