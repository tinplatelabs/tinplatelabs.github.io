Image OCR

Text from screenshots, scans and photos in reading order, with boxes and confidences.

Open Image OCR in the Apify Store

What it solves

Agents and pipelines need the text in screenshots, scanned letters, receipts and photos of documents, in the order a person would read it, and often where on the image each line is.

Image OCR runs PaddleOCR PP-OCRv6 on CPU inside your run and returns, per image, plain text and Markdown that keep paragraphs and line breaks, plus every line and word with its bounding box, polygon and confidence. Two-column prose is read column by column; forms and tables row by row, so a label stays next to its value.

  • On our test set of rendered and degraded text, 0.1% character errors against 6.8% for Tesseract.
  • English, Chinese, Japanese and 45+ Latin-script languages together with no setup; Russian, Greek, Arabic, Hebrew, Hindi, Korean, Thai and more via Tesseract.
  • EXIF orientation applied, pages turned 90/180/270 degrees detected, small images enlarged; coordinates in the pixels of the image you sent.
  • Up to 500 images per run, every page of a multi-page TIFF; URLs, key-value store files or data: URIs.

Anything that can't be processed becomes an error item with a code and a message that says what to change; the rest of the run carries on.

Limits

  • 30 MB per file, 50 megapixels per page, 50 pages per TIFF, 500 images per run.
  • PNG, JPEG, WebP, TIFF, BMP, GIF (first frame). Not PDF: use Document to Markdown for PDFs.
  • Printed text; handwriting only when neat. Tables come out row by row, without cell structure.
  • About 5 to 7 s per screenshot or letter at the default 2 GB.

Use it from an AI agent

Through the Apify MCP server, Claude, ChatGPT, Cursor and other MCP clients can call this Actor as a tool. Add the server with this Actor enabled:

{
  "mcpServers": {
    "apify": {
      "url": "https://mcp.apify.com/?tools=tinplatelabs/image-ocr",
      "headers": {
        "Authorization": "Bearer <APIFY_TOKEN>"
      }
    }
  }
}

The agent calls it with {"images": ["https://example.com/screenshot.png"]} and reads text or markdown from the dataset item, and lines[].box to locate what was read.

Or call the Apify API directly. This runs the Actor and returns the dataset items (synchronous runs time out after 300 s; for big batches start a run and read the dataset when it finishes):

curl -s -X POST \
  "https://api.apify.com/v2/acts/tinplatelabs~image-ocr/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"images": ["https://example.com/screenshot.png"]}'

FAQ

Can it read PDFs?

No, images only. For PDFs, including scanned ones, use Document to Markdown, which OCRs pages without a text layer.

Which languages are supported?

With no setting, English, Chinese, Japanese and 45+ Latin-script languages are read together. Name other languages by ISO code in languages (e.g. ru, ar, ko) to switch to Tesseract.

How do I get the position of each line?

Each entry in lines has a box, a 4-point polygon, its block and paragraph number and a confidence; each word has its own box. Coordinates are in the original image's pixels.

Can I send an image inline?

Yes, as a base64 data:image/png;base64,... URI, or upload it to a key-value store and pass kvs://KEY.

Does more memory cost more?

No. The price per image is the same at any memory; 4 GB is up to twice as fast as the default 2 GB.
