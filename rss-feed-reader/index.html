Feeds or websites in, clean JSON posts out, with only-new monitoring and optional full articles.

Open RSS Feed Reader & Feed Finder in the Apify Store

What it solves

Every feed format names things differently: RSS has pubDate and description, Atom has updated and content, JSON Feed has date_published and content_html. Many sites don't link their feed at all, half the feeds have broken XML, and a scheduled job has to remember what it already saw.

RSS Feed Reader takes feed URLs or just websites, finds the feed when needed, and returns every post with the same fields: title, link, guid, ISO dates, author, summary, content as text, Markdown or HTML, categories, image, enclosures and media, plus the feed's own details. With only-new mode a schedule delivers just the posts it has not seen, and unchanged feeds are answered with a cheap 304.

  • RSS 0.9x, 1.0 (RDF) and 2.0, Atom 0.3 and 1.0, JSON Feed 1.0 and 1.1; broken XML is recovered and flagged.
  • Feed finder for websites: <link rel="alternate">, feed links on the page, then common paths such as /feed, /rss.xml, /atom.xml and /index.xml; comment feeds come last.
  • Only new items: per-feed memory in a key-value store in your account, plus ETag / Last-Modified conditional requests.
  • Filters: newest first, max items per feed, only items published after a date or an age such as 7 days.
  • Content as plain text, Markdown, sanitized HTML or none; podcast audio in enclosures, Media RSS in media.
  • Optional full article per item, main content as Markdown, robots.txt obeyed.
  • Feed summary in the key-value store: status per feed, items delivered, already seen and filtered out.

Anything that can't be processed becomes an error item with a code and a message that says what to change; the rest of the run carries on.

Limits

  • 5,000 feed URLs or websites per run; 10 MB per feed; full articles up to 5 MB and 100,000 Markdown characters.
  • Public feeds only: no logins, no paywalls, no private addresses.
  • JavaScript is not executed, so articles that only render in a browser come out short.
  • robots.txt is obeyed for guessed feed paths and full-article pages.

Use it from an AI agent

Through the Apify MCP server, Claude, ChatGPT, Cursor and other MCP clients can call this Actor as a tool. Add the server with this Actor enabled:

{
  "mcpServers": {
    "apify": {
      "url": "https://mcp.apify.com/?tools=tinplatelabs/rss-feed-reader",
      "headers": {
        "Authorization": "Bearer <APIFY_TOKEN>"
      }
    }
  }
}

The agent calls it with {"startUrls": ["https://blog.example.com"], "maxItemsPerFeed": 5, "contentFormat": "markdown"} and reads title, link, published and content from the dataset items.

Or call the Apify API directly. This runs the Actor and returns the dataset items (synchronous runs time out after 300 s; for big batches start a run and read the dataset when it finishes):

curl -s -X POST \
  "https://api.apify.com/v2/acts/tinplatelabs~rss-feed-reader/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"startUrls": ["https://blog.example.com"], "maxItemsPerFeed": 5, "contentFormat": "markdown"}'

FAQ

How does only-new mode know what is new?

Each item gets a key from its guid (else its link, else title and date). The keys of the items in each feed are kept in a key-value store named feed-reader-only-new-<onlyNewKey> in your account, with the feed's ETag and Last-Modified. Delete the store to start over.

Do I need the feed URL?

No. Give the website (for example theverge.com) and the Actor finds its feed. Giving the feed URL saves a request.

Can it read podcasts?

Yes. Podcast feeds are RSS; the audio files are listed in enclosures with type and size.

Why is the content only a teaser?

Many feeds publish only an excerpt. Turn on fetchFullArticle to fetch each page and add its main content as Markdown.
