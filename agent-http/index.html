What it solves

Agents that call APIs or read web pages get raw HTML full of navigation and cookie banners, multi-megabyte bodies that flood the context window, and no help with retries, redirects or rate limits.

HTTP Request Tool for Agents sends a batch of requests and returns one clean record per request: status, headers, the body as parsed JSON or as Markdown of the page's main content, the full redirect chain, a timing breakdown and TLS certificate details. A token budget cuts long bodies at a paragraph boundary and says so. A URL health mode checks lists of links.

  • maxBodyTokens (default 8,000) keeps one huge page from flooding the context.
  • Retries on 429/5xx and connection failures with backoff, honouring Retry-After; POST/PATCH only retried when safe.
  • Private, loopback, link-local and cloud-metadata addresses refused, also after redirects and DNS resolution.
  • Authorization, cookies and API-key headers redacted in output and log; credentials not forwarded to another host on redirect.
  • Binary bodies saved to the key-value store and returned as a URL.

Example input

{
  "requests": [

Anything that can't be processed becomes an error item with a code and a message that says what to change; the rest of the run carries on.

Pricing

Pay per event: you pay for results, not for compute time. Prices in USD.

EventPriceWhen
request-completed$0.001Each request that received an HTTP response, any status code (retries and redirects included)

1,000 requests cost $1. A 404 or 500 is a response and is charged; DNS failures, timeouts, blocked addresses and invalid input cost nothing. When a run reaches the maximum total charge you set, it stops cleanly and marks what's left SPENDING_LIMIT_REACHED.

Limits

  • 10,000 requests per run; HTTP/1.1 only.
  • JavaScript is not executed: pages rendered in the browser come back nearly empty.
  • HTML larger than 2 MB is converted from its first 2 MB; downloads up to 50 MB per body (10 MB default).
  • Only public internet addresses are reachable.

Use it from an AI agent

Through the Apify MCP server, Claude, ChatGPT, Cursor and other MCP clients can call this Actor as a tool. Add the server with this Actor enabled:

{
  "mcpServers": {
    "apify": {
      "url": "https://mcp.apify.com/?tools=tinplatelabs/agent-http",
      "headers": {
        "Authorization": "Bearer <APIFY_TOKEN>"
      }
    }
  }
}

The agent calls it with {"requests": [{"url": "https://example.com"}]} and reads statusCode, bodyFormat and body from the dataset items.

Or call the Apify API directly. This runs the Actor and returns the dataset items (synchronous runs time out after 300 s; for big batches start a run and read the dataset when it finishes):

curl -s -X POST \
  "https://api.apify.com/v2/acts/tinplatelabs~agent-http/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"requests": [{"url": "https://example.com"}]}'

Privacy

Requests go only to the URLs you give (and their redirects). Secrets in headers are redacted in the dataset and log. No third party, no LLM, no telemetry. See also the privacy page.

FAQ

Is this a web scraper?

No. It is a plain HTTP client: no proxy rotation, no fingerprint spoofing, no CAPTCHA or anti-bot evasion, and the default User-Agent identifies the Actor. You are responsible for the terms of the sites and APIs you call.

How do I pass an API key safely?

Use the authorization input (stored encrypted, never output) or per-request headers. Authorization, cookie and API-key headers and query parameters are redacted in the dataset and log.

What does an agent get for an HTML page?

Markdown of the main content, with navigation, cookie banners, sidebars and footers stripped and links made absolute, cut to the token budget. Use htmlFormat for full-page Markdown, text or raw HTML.

Can it check a list of links for broken ones?

Yes. mode: url-health returns broken, the reason (e.g. HTTP 404, DNS_FAILED), redirect count, response time and TLS days left, without downloading bodies.

Why are 404 responses charged?

A 404 is a successful HTTP exchange with an answer you can act on. Only requests that get no response at all are free.
