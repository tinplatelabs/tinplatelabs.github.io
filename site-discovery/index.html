Site Discovery

Every sitemap URL, robots.txt access for AI crawlers and llms.txt for any site, as JSON.

Open Site Discovery in the Apify Store

What it solves

To know whether GPTBot or ClaudeBot may read a site, or to get a site's URL inventory without crawling it, you need a correct robots.txt matcher and a sitemap reader that survives what sites actually publish: gzip with the wrong Content-Type, broken namespaces, nested indexes, HTML error pages served with status 200.

Site Discovery returns one record per site with robots.txt rules per user agent, an allowed/disallowed verdict for each AI and search crawler (with the rule that decided), every sitemap found and expanded into a deduplicated URL list, and the site's llms.txt parsed into sections. A check mode answers "may user agent Y fetch URL X?".

  • RFC 9309 robots.txt matching: exact product-token groups, longest match wins, Allow wins ties, wildcards, and the RFC rules for missing (4xx) and broken (5xx) files.
  • Sitemaps streamed (no 50 MB file held in memory), indexes expanded recursively, URLs deduplicated; filter by prefix or regex.
  • Partial beats failed: one broken sitemap gets its own error entry and the rest of the site is still returned.
  • Polite: fetches only robots.txt, sitemaps, llms.txt and llms-full.txt, never pages; requests identify themselves and are paced per host.

{

Anything that can't be processed becomes an error item with a code and a message that says what to change; the rest of the run carries on.

Limits

  • 1,000 sites (or 10,000 URLs to check) per run; up to 200,000 returned URLs per site.
  • Up to 2,000 sitemap files per site, nested up to 6 levels; 100 MB per uncompressed sitemap.
  • User-agent groups match by exact product token (RFC 9309); Google's fallback from e.g. Googlebot-Image to Googlebot is not applied.
  • llms.txt returned up to 100,000 characters; llms-full.txt is summarized, not returned.

Use it from an AI agent

Through the Apify MCP server, Claude, ChatGPT, Cursor and other MCP clients can call this Actor as a tool. Add the server with this Actor enabled:

{
  "mcpServers": {
    "apify": {
      "url": "https://mcp.apify.com/?tools=tinplatelabs/site-discovery",
      "headers": {
        "Authorization": "Bearer <APIFY_TOKEN>"
      }
    }
  }
}

The agent calls it with {"sites": ["example.com"], "includeUrls": false} and reads crawlerAccess, llmsTxt and urls from the dataset item.

Or call the Apify API directly. This runs the Actor and returns the dataset items (synchronous runs time out after 300 s; for big batches start a run and read the dataset when it finishes):

curl -s -X POST \
  "https://api.apify.com/v2/acts/tinplatelabs~site-discovery/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"sites": ["example.com"], "includeUrls": false}'

FAQ

Does this crawl the website?

No. It fetches only the files sites publish for machines: /robots.txt, sitemaps, /llms.txt and /llms-full.txt. No page is ever crawled.

Which AI crawlers are checked by default?

A list of common AI and search crawlers such as GPTBot, ClaudeBot, Google-Extended and PerplexityBot. Pass userAgents to choose your own product tokens, including *.

What if robots.txt returns a server error?

As RFC 9309 says, a 5xx or unreachable robots.txt means everything is disallowed, and a 4xx means everything is allowed. The robotsTxt.status field tells you which applied.

Can I get only the counts, not the URL list?

Yes. includeUrls: false returns counts only and has no URL fees.

Where does it look for sitemaps?

Sitemaps declared in robots.txt first; otherwise /sitemap.xml, /sitemap_index.xml and /wp-sitemap.xml.
