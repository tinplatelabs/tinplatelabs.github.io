What it solves

Traefik is configured on Docker through long, dotted labels such as traefik.http.routers.api.middlewares. A typo in one of them is silently ignored by Traefik, and the right segment names live in a reference page you have to keep open.

Traefik Labels makes the IDE understand those labels in Compose files:

  • Completion for every traefik.* label segment, for router, service and middleware names defined in the file, and for values.
  • Warnings for unknown and incomplete labels, with did-you-mean quick-fixes.
  • Hover documentation with a link to the matching Traefik reference page.

Example

services:
  whoami:
    image: traefik/whoami
    labels:
      - traefik.enable=true
      - traefik.http.routers.whoami.rule=Host(`whoami.example.com`)
      - traefik.http.routers.whoami.entrypoints=websecure
      - traefik.http.routers.whoami.tls.certresolver=le
      - traefik.http.services.whoami.loadbalancer.server.prot=80   # warning: unknown label, did you mean ...server.port?

Typing traefik.http.routers.whoami. offers rule, entrypoints, tls, middlewares and the other router options; the misspelt prot is underlined with a quick-fix to port.

Install

In the IDE: Settings → Plugins → Marketplace, search for Traefik Labels, install and restart. Or install from the Marketplace page.

FAQ

Which IDEs does it work in?

Every JetBrains IDE with the bundled YAML plugin, version 2025.3 or newer: IntelliJ IDEA, PyCharm, GoLand, WebStorm, PhpStorm, Rider, RubyMine, CLion and the rest.

Does it need a network connection or send telemetry?

No. The label schema ships inside the plugin, and it never makes network requests.

Where does the label list come from?

It is generated from Traefik's own label reference for a specific Traefik release, never written by hand, so labels and their documentation match Traefik.

Does it understand labels in list form and under deploy?

Yes. Labels in map form and list form, under labels and deploy.labels, are supported.

Why isn't a value with ${VAR} flagged?

Compose interpolates ${...} before Traefik reads the label, so the plugin never reports a problem on such a value.
