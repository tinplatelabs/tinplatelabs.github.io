What it solves

Agents and pipelines can't watch video. They need a handful of well-chosen still frames with exact timestamps: for thumbnails, storyboards, vision-model datasets, moderation queues or to hand a video to a multimodal LLM as images.

Video Frames reads the video files you supply with ffmpeg and returns frames in the mode you pick: N evenly spaced, every N seconds, exact timestamps, every keyframe, the first frame of every scene, or the single best thumbnail. Each frame comes with its timestamp, timecode and size, each video with its duration, fps, resolution and codecs.

  • Six modes in one Actor, all limited to a start/end range if you like; timestamps as seconds, timecodes or percentages.
  • Scene detection with adjustable sensitivity and minimum scene length, with a scene-change score per frame.
  • Best thumbnail: candidates scored for sharpness, exposure and detail, skipping fades at the start and end.
  • JPEG, PNG or WebP, scaled to a maximum width; optional contact sheet with timecode labels.
  • Your files only: links to YouTube, TikTok and other platforms are refused, free of charge.

Limits

  • 2 GB per file, 100 videos per run, up to 600 minutes per video (default limit 240), up to 5000 frames per video (default 300).
  • The first video track is used; HDR is tone-mapped by ffmpeg's default conversion.
  • Platform page links (YouTube, TikTok, Instagram, Vimeo, Twitch and similar) are refused.
  • Seeking modes are fast on any length; scenes mode decodes every frame (roughly real time for 1080p at the default 2 GB).

Use it from an AI agent

Through the Apify MCP server, Claude, ChatGPT, Cursor and other MCP clients can call this Actor as a tool. Add the server with this Actor enabled:

{
  "mcpServers": {
    "apify": {
      "url": "https://mcp.apify.com/?tools=tinplatelabs/video-frames",
      "headers": {
        "Authorization": "Bearer <APIFY_TOKEN>"
      }
    }
  }
}

The agent calls it with {"videos": ["https://example.com/clip.mp4"], "mode": "count", "frameCount": 8, "maxWidth": 768} and reads each frame's url and timestamp from the dataset items, and the type: video summary for duration, fps and resolution.

Or call the Apify API directly. This runs the Actor and returns the dataset items (synchronous runs time out after 300 s; for big batches start a run and read the dataset when it finishes):

curl -s -X POST \
  "https://api.apify.com/v2/acts/tinplatelabs~video-frames/run-sync-get-dataset-items" \
  -H "Authorization: Bearer $APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"videos": ["https://example.com/clip.mp4"], "mode": "count", "frameCount": 8, "maxWidth": 768}'

Privacy

Videos are processed inside your run; results go only to its dataset and key-value store. No third party, no telemetry, and only the exact URLs you give are fetched. See also the privacy page.

FAQ

Can I get frames from a YouTube video?

No. Video Frames works on files you supply and have the rights to. Platform page links get a free PLATFORM_URL_NOT_SUPPORTED error. Upload the file to a key-value store or give a direct link to your own storage.

Which mode should I use?

count for a quick overview, interval for regular sampling, scenes for one frame per shot, keyframes for the encoder's own I-frames, thumbnail for one cover image.

How accurate are the timestamps?

Each frame reports the time it was actually taken at, to the millisecond, plus its timecode and frame number.

Where are the images?

In the run's key-value store, linked from each dataset item with a signed URL that works without an Apify token.

Is my video sent anywhere?

No. ffmpeg runs inside your Apify run; nothing is sent to a third party.
